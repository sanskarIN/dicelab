# Development Setup

DiceLab supports six runtime targets from one codebase:

1. the Vite web companion;
2. Windows through Tauri 2;
3. macOS through Tauri 2;
4. Linux through Tauri 2;
5. Android through Tauri 2 mobile;
6. iOS/iPadOS through Tauri 2 mobile.

The shared React/TypeScript application and Rust domain/native core are reused across these targets. Platform-generated Android/iOS projects live under `src-tauri/gen/` and are generated by the Tauri CLI rather than maintained as hand-edited application source.

## Common prerequisites

Install:

- Git;
- Node.js 22 or newer;
- npm;
- Rust stable through rustup for native work.

Clone the repository:

```bash
git clone https://github.com/sanskarIN/dicelab.git
cd dicelab
npm ci
```

Run only the web companion:

```bash
npm run dev
```

## Web companion

The browser build has no native Tauri prerequisite. Use:

```bash
npm run dev
npm run build
npm run test:e2e
```

The production browser companion uses ordinary browser downloads for exports. Native builds use the reviewed Tauri dialog/filesystem route instead.

## Windows desktop prerequisites

Use a supported Windows version and install the tools required by Tauri 2, including:

- Microsoft C++ Build Tools / Visual Studio C++ desktop workload;
- Microsoft Edge WebView2 where it is not already provided by the OS;
- Rust stable with the MSVC toolchain.

Then:

```powershell
rustup default stable-msvc
npm run tauri:dev
```

Build a desktop bundle with:

```powershell
npm run tauri:build
```

## macOS desktop prerequisites

Install Xcode command-line tools:

```bash
xcode-select --install
```

Install Rust stable, then:

```bash
npm run tauri:dev
npm run tauri:build
```

Release signing/notarization is separate and requires credentials that must never be committed.

## Linux desktop prerequisites

The exact package names vary by distribution. On Ubuntu/Debian development machines, CI installs:

```bash
sudo apt-get update
sudo apt-get install -y --no-install-recommends \
  libwebkit2gtk-4.1-dev \
  build-essential \
  curl \
  wget \
  file \
  libxdo-dev \
  libssl-dev \
  libayatana-appindicator3-dev \
  librsvg2-dev
```

Then:

```bash
npm run tauri:dev
npm run tauri:build
```

For another distribution, install the equivalent packages from that distribution following the current Tauri prerequisite guide.

## Android prerequisites

DiceLab targets **Android API 24+**. Android native development requires:

- a supported JDK (CI uses Java 17);
- Android SDK Platform/Platform Tools;
- Android SDK Build Tools;
- Android command-line tools;
- Android NDK;
- `ANDROID_HOME` pointing to the Android SDK;
- `NDK_HOME` pointing to the selected NDK installation;
- Rust Android targets.

Install the Rust targets when they are not already present:

```bash
rustup target add \
  aarch64-linux-android \
  armv7-linux-androideabi \
  i686-linux-android \
  x86_64-linux-android
```

Initialize the generated Android project once per clean checkout/tooling reset:

```bash
npm run tauri:android:init
```

Run on an emulator or attached device:

```bash
npm run tauri:android:dev
```

Build APK and AAB outputs:

```bash
npm run tauri:android:build
```

For a faster ARM64-only validation build:

```bash
npm run tauri:android:build -- --target aarch64
```

The tagged release workflow builds universal Android validation artifacts. Google Play publication additionally requires a private Android signing keystore and Play Console setup; those secrets must not be committed.

## iOS and iPadOS prerequisites

DiceLab targets **iOS/iPadOS 14.0+**. Tauri iOS commands require a macOS host. Install:

- Xcode with the iOS platform components;
- Xcode command-line tools;
- Rust through rustup;
- the required iOS Rust targets.

For physical-device and Apple Silicon simulator builds:

```bash
rustup target add aarch64-apple-ios aarch64-apple-ios-sim
```

For Intel simulator support where needed:

```bash
rustup target add x86_64-apple-ios
```

Initialize the generated Apple project:

```bash
npm run tauri:ios:init
```

Run on a simulator or attached device:

```bash
npm run tauri:ios:dev
```

Build through the normal Tauri/Xcode signing flow:

```bash
npm run tauri:ios:build
```

CI validates an Apple Silicon simulator build without requiring an App Store identity:

```bash
npm run tauri:ios:build:ci
```

The locked Tauri CLI also supports the repository's unsigned archive validation command:

```bash
npm run tauri:ios:archive:ci
```

App Store distribution still requires Apple Developer enrollment, a registered bundle identifier, signing certificate/provisioning, and App Store Connect configuration. Keep all signing material outside Git.

## Mobile dev-server behavior

`vite.config.ts` already honors `TAURI_DEV_HOST`. Tauri supplies that value when a physical mobile device needs to reach the development server over the local network, so contributors should not hard-code a device IP into committed configuration.

## Native export behavior across platforms

The renderer never receives broad filesystem access. CSV/JSON export uses the same bounded Rust command on desktop and mobile:

- desktop/iOS selections can resolve to normal paths/file URLs;
- Android document providers may return `content://` URIs;
- `tauri-plugin-fs` opens the selected `FilePath` without granting generic renderer filesystem permissions;
- iOS security-scoped access is explicitly released after the write;
- browser builds retain Blob/download behavior.

Physical-device release evidence should include at least one export/restore smoke on Android and iOS because document-provider and OS-dialog behavior cannot be proven by compiler-only CI.

## Verify toolchains

```bash
node --version
npm --version
rustc --version
cargo --version
```

Then run the common project verification:

```bash
npm run format
npm run lint
npm run test
npm run build
npm run policy:all

cd src-tauri
cargo fmt --all -- --check
cargo test --locked
cargo clippy --all-targets --all-features --locked -- -D warnings
```

Mobile build jobs in `.github/workflows/ci.yml` provide additional Android and iOS compile evidence on every main-branch push and pull request.

## Environment variables

DiceLab does not require production API keys for its core workflows. See `.env.example` for the intentionally minimal application configuration surface.

Never place secrets in `VITE_*` variables: Vite frontend variables are bundled into client assets.

Platform signing credentials belong only in secure local credential stores or CI secrets. Never commit Android keystores, provisioning profiles, Apple certificates/API keys, or their passwords.

## Editor recommendations

Any editor is supported. Useful capabilities include:

- TypeScript language service;
- ESLint integration;
- Prettier integration;
- rust-analyzer;
- rustfmt on save.

Repository `.editorconfig` settings should remain authoritative for basic whitespace behavior.
